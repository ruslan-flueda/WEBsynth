# Архитектура WEBsynth V2

## Загрузка и зависимости

Приложение использует обычные `defer`-скрипты, перечисленные в `src/index.html`. Это сохраняет прямое открытие через `file://` без сервера. Каждый файл изолирован собственной функцией; единственное общее пространство имён — `window.WebSynth`. Порядок загрузки: конфигурация → музыкальные данные → аудио → секвенсор → UI → `main.js`.

ES-модули и сборщик здесь не используются. `scripts/build.mjs` копирует читаемые исходники и ресурсы в `dist/`, сохраняя структуру. HTML служит единым списком загрузки и для браузера, и для тестов. При добавлении файла подключите его перед первым потребителем.

## Кто хранит состояние

| Объект | Ответственность |
| --- | --- |
| `config`, `lanes` | Неизменяемые настройки сетки и определения ползунков |
| `patterns` | Исходные музыкальные события |
| `Sequencer` | BPM, паттерны, seeds перемешки, Solo, очередь будущих шагов |
| `Engine` | AudioContext, текущие параметры каналов, команды аудиосистеме |
| `AudioChannel` | Узлы одного канала и их автоматизация |
| `Synthesis` | Создание и завершение всех источников звука, включая фон Chords |
| `Effects` | Общий аудиограф эффектов и выход |
| `App` | Обработка действий пользователя, сообщения и состояние кнопки Play |
| `ChannelView` | DOM одного канала; получает состояние из секвенсора |

UI не создаёт осцилляторы. Секвенсор не обращается к DOM. Тембры не выбирают музыкальные паттерны. Настройки эффектов используют ключи `reverb`, `delay`, `vibrato` и т. д., поэтому перевод подписей не меняет поведение аудио.

## Музыкальное событие

```js
event(2, "melody", 74, 2, 0.82)
// Возвращает:
// { step: 2, sound: "melody", note: 74, duration: 2, velocity: 0.82 }
```

`step` и `duration` измеряются в шестнадцатых. `note` — MIDI-номер, массив MIDI-номеров для аккорда или `null` для ударного звука. `sound` ссылается на функцию из `voices.js`. Каждая вариация содержит четыре массива тактов. Индекс вариации `0` зарезервирован для выключенного канала.

Shuffle возвращает новые события со смещённым шагом. Ноты на нулевом шаге закреплены; остальные сдвигаются на 1–3 шага в пределах такта с учётом длительности. Один seed даёт один и тот же ритм при повторении. Исходные события и массивы нот внутри них заморожены; коллекции вариаций используются только для чтения. Результат перемешки вычисляется один раз на такт.

## Время и переключения

Источник времени — `AudioContext.currentTime`. Таймер просыпается каждые 25 мс и планирует события примерно на 100 мс вперёд; `requestAnimationFrame` обновляет только отображение. Уже поставленные в аудиоочередь ноты не пересчитываются при изменении BPM. Новый темп применяется к последующим шагам; delay плавно подстраивается.

Выбор паттерна и Shuffle сначала попадают в отдельные очереди `pendingPatterns` и `pendingShuffles`. На первом шаге следующего такта секвенсор применяет их и запоминает время в `scheduledPatterns` / `scheduledShuffles`. Эти отметки позволяют показывать ожидание между планированием события и его фактическим звучанием. Изменение, которое уже передано аудиодвижку, считается зафиксированным; дальнейший клик создаёт следующий запрос.

Solo управляет отдельным gain-узлом, не отменяя автоматизацию включения паттерна. Секвенсор продолжает планировать активные каналы под Solo, чтобы при возврате микса они оставались на общей сетке. При длительной задержке таймера транспорт продолжает с ближайшего будущего времени без залпа просроченных нот; точное настенное время после фонового throttling не восстанавливается.

## Путь аудиосигнала

В каждом канале:

```text
источники → lowpass → dry ──────────┐
                    → drive → wet ─┴→ pattern gate → solo gate → volume
```

После громкости сигнал поступает в сухой общий тракт и индивидуальные посылы reverb/delay. Общие пути сходятся перед компрессором, master gain и лимитером. Задержка — пунктирная восьмая (`60 / BPM × 0.75`) с фильтрованной обратной связью. Ревербератор использует сгенерированный шумовой импульс.

При Stop master плавно затухает, затем останавливаются все источники, включая атмосферный фон. Завершившиеся источники и связанные узлы отключаются в `onended`. При следующем Play общий блок эффектов пересоздаётся, чтобы хвосты предыдущего запуска не возвращались. AudioContext переиспользуется.

## Добавление инструмента

1. Добавьте описание канала и его ползунков в `config.js`.
2. Создайте файл паттернов в `music/patterns/` и подключите его в `index.html`.
3. Зарегистрируйте звуки в `voices.js`. Используйте `Synthesis.tone`, `noise` и `track` для корректного завершения источников.
4. Для нового типа эффекта добавьте семантический ключ и обработку в нужном аудиомодуле.
5. Проверьте адаптивную раскладку и обновите тесты/README. Контрольную сумму композиции меняйте только при намеренной правке музыкального материала.

В новом коде используйте два пробела, осмысленные имена и небольшие функции с одной задачей. Комментарии нужны для музыкальных решений, времени и жизненного цикла, а не для пересказа каждой строки.
